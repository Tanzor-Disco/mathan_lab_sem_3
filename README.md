# Лабораторная работа по математическому анализу

Условие и параметры вариантов находятся в [`tasks/main.pdf`](tasks/main.pdf). Работа состоит из трёх разделов. Параметры двойных и тройных интегралов берём из приложения А, параметры модели автоскейлинга — из приложения Б. Номер варианта общий для всей команды.

## Структура репозитория

```text
.
├── tasks/                       # условие работы в PDF и LaTeX
├── programming/
│   ├── main.py                  # общий запуск экспериментов
│   ├── requirements.txt         # зависимости Python
│   ├── double_integrals/        # §1. Двойные интегралы
│   ├── triple_integrals/        # §2. Тройные интегралы
│   └── autoscaling/             # §3. Модель автоскейлинга
├── math/                        # отдельные .tex-файлы разделов отчёта
├── figures/                     # рисунки и графики, созданные программой
├── report_examples/             # примеры оформления
└── report.tex                   # главный файл общего отчёта
```

## Python-код

Код каждого раздела пишем в соответствующей папке внутри `programming/`. Вычислительные функции принимают параметры задачи и возвращают результаты. Код эксперимента подставляет параметры нашего варианта, запускает расчёты, собирает результаты и готовит таблицы и графики.

Например, в §1 вычислительная функция считает интеграл на одной сетке. Эксперимент вызывает её для всех размеров сетки, сравнивает приближения с точным значением и по полученным данным выводит таблицу и строит график ошибки. Численные методы интегрирования в §1 и §2 реализуем самостоятельно.

`programming/main.py` запускает эксперименты всех трёх разделов. **Все графики и рисунки областей программа сохраняет в `figures/` в корне репозитория.** Код создаёт эту папку при необходимости. Таблицы печатаем в терминал и переносим в соответствующий раздел отчёта. Для таблицы и графика используем одни и те же результаты расчёта.

## LaTeX-отчёт

Каждый пишет свой раздел в отдельном `.tex`-файле внутри `math/`. В этом файле размещаем математические выкладки, результаты расчётов, таблицы, рисунки и выводы.

**Главный файл отчёта — `report.tex` в корне.** В нём находятся преамбула, титульный лист и подключения файлов из `math/` в порядке разделов. Например, файл `math/double_integrals.tex` подключается так.

```latex
\input{math/double_integrals}
```

Рисунок подключаем в том `.tex`-файле, к которому он относится. Путь указываем от корня репозитория.

```latex
\includegraphics[width=\linewidth]{figures/double_integral_error.pdf}
```

## Запуск и сборка

Нужен Python 3.10 или новее. На macOS и Linux выполните из корня репозитория:

```bash
python3 -m venv programming/.venv
source programming/.venv/bin/activate
python -m pip install -r programming/requirements.txt
python programming/main.py
```

После генерации рисунков соберите отчёт из корня репозитория.

```bash
xelatex report.tex
xelatex report.tex
```

Локальное окружение `programming/.venv/` и генерируемую папку `figures/` в Git не добавляем. В комплект сдачи включаем `report.pdf`, `report.tex`, подключаемые файлы из `math/`, Python-код с `requirements.txt` и все рисунки, использованные в отчёте.

## Проверка форматирования

GitHub Actions проверяет Black-форматирование папки `programming/` при пушах в `main` и в PR, нацеленных на `main`. Если Black установлен локально, применить форматирование можно из корня репозитория.

```bash
python -m black programming/
```
